# 🔨 Ultimate Hammer

**Minecraft Bedrock 1.26.44 · @minecraft/server `2.10.0-beta` · Behavior Pack + Resource Pack**

Молот, который ощущается как ванильный инструмент, но ломает **плоскую зону**:
обычный удар — **3×3**, присед — **1×1**, архитектура готова к **5×5** (`uh:radius 2`).
Скорость — на один материальный уровень выше соответствующей кирки.

> Спецификация: `Ultimate_Hammer_Addon_Spec_1.26.31.zip` (в корне репозитория).
> Реализация следует ТЗ: face + faceLocation + геометрия игрока, отдельная
> обработка Up/Down, гистерезис, фильтр блоков, дроп без дюпов, debug до
> финализации формулы.

---

## Установка

1. Возьми **`Ultimate_Hammer_v1.2.0.mcaddon`** (в корне репо, пересобирается `bash tools/build.sh`).
2. Открой двойным кликом / импортируй в Minecraft **1.26.44**.
3. В мире включи эксперимент **Beta APIs** (нужен для модуля `2.10.0-beta`).
4. Активируй **оба** пака в мире (BP — поведение, RP — текстуры/локализация). Без RP молоты будут с чёрно-фиолетовой текстурой.

В креативном инвентаре молоты стоят **сразу после кирок** — внутри раскрывающейся
группы «Кирки», порядок строгий: деревянный → каменный → железный → золотой →
алмазный → незеритовый (`item_catalog/crafting_item_catalog.json`).

Крафт (верстак, единая форма для всех материалов):

```
M M M        M: материал ×5   деревянный  — доски (любые)
M S M        S: палка ×2      каменный    — камень
 · S ·                        железный    — слитки железа
                              золотой     — слитки золота
                              алмазный    — алмазы
                              незеритовый — слитки незерита
```

> Рецепт T-образный (5 материалов + 2 палки) — классические «3+2» совпадают
> с ванильными кирками и создают конфликт рецептов.

## Как это работает

```
playerStartBreakingBlock ─┐
playerInteractWithBlock ──┤→ API Adapter (face, faceLocation из луча/тапа, поза игрока)
                          │→ Direction Resolver (чистая математика: зоны core/transition/periphery,
                          │   гистерезис) → плоскость X/Z · X/Y · Z/Y
                          │→ Area Generator (radius 0/1/2, всегда плоско)
завершение разрушения ────┘→ Block Filter (защита/контейнеры/спецблоки) → Executor
                          → Durability (per_block по умолчанию) → Drop (0% дюпов) → Debug
```

Ключевые решения (полный список — `docs/DECISIONS.md`):

- **Зона сносится в момент реального разрушения центрального блока** — центр
  честно копается ванильной механикой (скорость из `minecraft:digger`,
  энчанты Efficiency/Fortune/Silk Touch работают), затем сносит спутники.
  Дюп невозможен архитектурно: ручной дроп выключен, ванильный дроп выдаётся
  только центру.
- **`faceLocation`** добывается из `BlockRaycastHit` прицельного луча
  (`getBlockFromViewDirection`) и коррелируется с `playerInteractWithBlock`
  (touch). В `PlayerStartBreakingBlockAfterEvent` этого поля **нет** — проверено
  по официальному `@minecraft/server@2.10.0-beta.1.26.44-stable` (`.d.ts` с npm).
- **Направление СТРОГО по грани (v1.2.0)**: North/South → X/Y, West/East → Z/Y,
  Up/Down → всегда X/Z (яма/потолок). Направление взгляда в решении НЕ участвует
  (touch-паритет: камера может смотреть куда угодно). Плоскость у грани одна —
  «лотерея» и дрожание невозможны архитектурно.
- **Категория блоков как у кирки**: зона 3×3/5×5 ломает только блоки кирочной
  категории (камень, металлы, руды, лёд, рельсы…). Дерево, доски, горшки,
  лестницы, земля и прочее в зоне не трогаются (причина `wrong_tool` в логе).
- **Контейнеры и спецблоки** (сундуки, воронки, шалкеры, спавнеры, сундук
  Края, подозрительный песок…) из зоны исключаются — содержимое не теряется
  и не дюпается. Кастомные блоки карт (не `minecraft:`) неприкосновенны
  по умолчанию.

## Баланс

| Молот | Скорость (= кирка уровнем выше) | Прочность | Урон |
|---|---|---|---|
| Деревянный | 4 (каменная) | 60 | 2 |
| Каменный | 6 (железная) | 132 | 3 |
| Железный | 8 (алмазная) | 251 | 4 |
| Золотой | 13 (выше золотой 12) | 33 | 2 |
| Алмазный | 9 (незеритовая) | 1562 | 5 |
| Незеритовый | 12 (балансное, выше нет уровня) | 2032 | 6 |

Заточка — слот кирки (Efficiency, Fortune, Silk Touch, Unbreaking, Mending).
Чинится материалом и самим собой (`minecraft:repairable`).

## Команды (нужен читы: `/scriptevent uh:…`)

| Команда | Действие |
|---|---|
| `uh:help` | список команд |
| `uh:radius 0\|1\|2` | личная зона (2 = экспериментальный 5×5) |
| `uh:radius default` | сброс на серверную |
| `uh:debug on\|off\|chat` | отладка: actionbar+консоль / выкл / полный лог в чат |
| `uh:dump [n]` | последние n решений в чат |
| `uh:stats` | статистика ударов/блоков |
| `uh:config` | текущие пороги |
| `uh:selftest` | самопроверка математики в игре |

Каждое решение логируется строкой `[UHD]{json}` (консоль/лог) со всеми полями
протокола ТЗ 08: block/face/faceLocation/позиция/глаза/расстояние/локальные
координаты/плоскость/зона/уверенность/причины/кандидаты/результат.

## Отладка и калибровка (MCP)

`tools/mcp_debug_server.mjs` — MCP-сервер (stdio, без зависимостей), конфиг в
`.mcp.json`. Инструменты:

- **`uh_simulate`** — прогнать резолвер на любом синтетическом входе с патчем
  порогов (калибровка без запуска игры);
- **`uh_parse_log`** — вставь лог с `[UHD]`-строками → агрегаты по зонам/плоскостям;
- **`uh_checklist`** — протокол тестирования и чек-лист HM-001…HM-022;
- **`uh_config`** / **`uh_selftest`** — пороги/баланс и самопроверка.

## Разработка

```
npm test          # 19 юнит-тестов чистой математики (node --test)
bash tools/build.sh   # пересобрать Ultimate_Hammer_v1.2.0.mcaddon
python3 tools/gen_textures.py   # перегенерировать пиксельные текстуры
```

Структура: `behavior_packs/ultimate_hammer_bp/scripts/` — `config/detector/
adapter/resolver/area/filter/durability/drop/executor/logger/selftest/main`
(модули ТЗ 11_ARCHITECTURE; математика не зависит от API и не меняет мир).
Все пороги — в `config.js`; по результатам практических тестов правится
только он (`docs/EXPERIMENT_LOG.md` — журнал по шаблону ТЗ 15).

## Что проверять в первую очередь

1. `/scriptevent uh:selftest` — математика зелёная?
2. HM-004…007 — боковые грани дают вертикальные стены.
3. HM-008…013 — Up/Down: центр/край/угол/сбоку (ожидания в `uh:checklist`).
4. Дроп и прочность на смешанной зоне (HM-018…020).
5. Touch: те же точки, тапы по разным частям экрана (HM-014).

Сообщай «ожидалось → получено» (можно просто скрин actionbar или строку
`[UHD]`) — пороги в `config.js` подстрою под реальные данные.
