# Зафиксированные решения (реализация v1.0.0)

Дополняет `16_DECISIONS.md` исходного ТЗ пунктами, принятыми при реализации.

1. **Модуль API: `@minecraft/server` `2.10.0-beta`** — подтверждено пользователем
   для игры 1.26.44 (npm-пакет `2.10.0-beta.1.26.44-stable`); в мире включается
   эксперимент «Beta APIs».
2. **`faceLocation` в `PlayerStartBreakingBlockAfterEvent` отсутствует** (проверено
   по официальным `.d.ts` версий 2.9.0 / 2.10.0-beta.1.26.44 / 2.11.0-beta /
   2.12.0-beta и документации Microsoft Learn; свойство существует в 7 других
   классах: PlayerInteractWithBlock*, BlockRaycastHit, ItemUseOn, PlayerPlaceBlock,
   BlockComponentPlayerInteract, BlockHitInformation). Точка взаимодействия берётся из
   `BlockRaycastHit.faceLocation` прицельного луча + корреляция с
   `playerInteractWithBlock` (touch). Поля не выдуманы и не перенесены из чужих версий.
   Рантайм-контроль: первый удар в сессии дампит фактические ключи объекта события
   (`[UHD]{"rawEvent":…,"runtimeHasFaceLocation":…}`) — если движок тайно передаёт
   поле, это будет видно в логе и адаптер можно расширить.
3. **Срыв зоны = момент реального разрушения центрального блока**
   (`playerBreakBlock` + тиковый контроль для creative). Центр копается ванильно:
   скорость `minecraft:digger`, энчанты работают, зона не срабатывает от
   «тыканья» без завершения удара.
4. **Дроп**: по умолчанию `manualDrops=false` — дроп только у центра (ваниль),
   спутники через `setType(air)` ничего не дропают → дюп невозможен архитектурно.
   Экспериментальный ручной дроп (`getLoot`) — за флагом в `config.js`.
5. **Прочность**: `per_block` (1 блок = 1 ед.) — первая модель по ТЗ;
   `per_swing`/`hybrid` переключаются в конфиге без правки кода.
6. **Up/Down периферия**: вертикальная плоскость только при трёх одновременных
   условиях — игрок вне контура блока (`lateral > 0.8`), боковой зазор
   `< 1.05 м`, глаз у плоскости грани (`< 0.35 м`). Иначе — остаёмся на X/Z
   («главная проблема» из ТЗ 04: не превращать близкий боковой случай в стену).
   Нормаль стены перпендикулярна доминирующей оси смещения.
7. **Гистерезис**: смена плоскости требует уверенности `≥ 0.8 + hysteresis`;
   уверенные решения: core 0.95, вертикаль 0.90, transition 0.70, periphery-XZ 0.55.
8. **Фильтр зоны**: bedrock/командные/портальные блоки — абсолютный запрет;
   контейнеры и спецблоки — исключение из зоны (центр ванилен); любые блоки
   вне namespace `minecraft:` — неприкосновенны (защита чужих карт/аддонов).
9. **Creative**: зона срабатывает без расхода прочности; зона ограничена
   `reachDistance` и `maxZonePerTick=25` (HM-022).
10. **Тайминги**: `minBreakTicks=3` — защита от мгновенного «дам-дам» по
    непрогретой цели; pending живёт до 60 с и снимается `playerCancelBreakingBlock`.
11. **Скорости молотов** = кирка материала N+1: wood 4, stone 6, iron 8,
    diamond 9, netherite 12 (балансное, ТЗ 01), golden 13 (выше золотой кирки,
    сохраняет трейт «золото — самое быстрое, самое хрупкое»: прочность 33).
    Теги `stone/metal/diamond_pick_diggable` + явные записи (обсидиан только
    для алмаза/незерита, рельсы, лёд, спавнер).
12. **Локализация RU/EN** — `texts/*.lang`: названия, описание, режимы,
    строки actionbar. Внутриигровые команды отвечают по-русски (язык клиента
    скриптами не определить).
13. **Отладка включена по умолчанию** (actionbar + `[UHD]{json}` в консоль) —
    стадия эксперимента по ТЗ 14_ROADmap v0.1–0.4.
14. **5×5 доступно сразу** через `/scriptevent uh:radius 2` (в ТЗ — будущая
    прокачка; генератор радиуса 2 сквозной, HM-003/022 проверяемы уже сейчас).

15. **Рецепт — T-образный: `MMM/MSM/·S·` (5 материалов + 2 палки)**. Набор
    «3 материала + 2 палки» идентичен ванильным киркам → движок 1.26.44
    регистрирует duplicate crafting_table recipe (конфликт выдачи).
16. **`menu_category.group` обязан иметь namespace** —
    `minecraft:itemGroup.name.pickaxe`; без префикса парсинг предмета падает
    целиком (лог: "string must be prefixed with a namespace").
17. **`minecraft:powered_rail` в Bedrock не существует** — золотые рельсы
    это `minecraft:golden_rail` (в destroy_speeds нужен именно он).
18. **Текстуры молотов диагональные**: рукоять ЮЗ → боёк СВ, яркая ударная
    грань на СЗ, тёмный контур силуэта; иконки паков — градиент, свечение
    у бойка, бевел-рамка. UI-ошибки `recovery_compass`/`hud_screen` и
    `screen_world_controls_and_settings` в логах — ванильный шум движка,
    к аддону отношения не имеют.

## v1.1.0 (по итогам практических тестов)

19. **Креативное меню**: молоты — отдельная группа «Молоты/Hammers»
    (`item_catalog/crafting_item_catalog.json`, формат 1.26.40) со своей
    иконкой; порядок в группе задан массивом items: деревянный → … →
    незеритовый. Кастомные namespace-группы в menu_category без каталога
    движком не поддерживаются.
20. **Привязка RP**: BP dependency требует RP uuid ВЕРСИИ [1,1,0] — при
    обновлении guaranteeed подхватывается новый ресурспак, а не старый 1.0.0.
21. **Ось вертикальной стены при Up/Down задаётся горизонтальной
    составляющей ЛУЧА ВЗГЛЯДА**, а не смещением игрока относительно блока
    (смещение давало «стену в неожиданную сторону» — лотерея). Условие
    вертикали: точка вне центральной зоны + |view.y| ≤ 0.55 + цель вне
    контура игрока. Крутой взгляд вниз/вверх → всегда X/Z.
22. **Гонки исполнителя** («молот ломает только 1 блок»): (а) break чужого
    блока больше НЕ удаляет pending; (б) playerCancelBreakingBlock получает
    grace 10 тиков (в Bedrock cancel может прилететь ПЕРЕД break); (в) зона
    восстанавливается по последнему playerStartBreakingBlock (recentStarts,
    окно 60 тиков) если pending потерян.
23. **Частицы при разрушении зоны выключены** по умолчанию
    (CONFIG.debug.particles=false).
24. **Текстуры**: голова-кувалда ПОПЕРЁК рукояти (не «лопата» вдоль),
    боёк на СЗ; иконки паков 512×512 с градиентом/свечением/бевелом.

## v1.2.0 (по требованиям владельца)

25. **Направление СТРОГО по грани**: North/South→X/Y, West/East→Z/Y,
    Up/Down→ВСЕГДА X/Z. Взор/позиция игрока из решения УДАЛЕНЫ (touch:
    камера и тап не совпадают) — неоднозначность и «лотерея» невозможны
    архитектурно. faceLocation остаётся только для диагностики зон.
26. **Креатив**: `can_destroy_in_creative: true` (false запрещал молоту
    ломать блоки в креативе) + reach 8 м (креативная дальность выше
    выживания) + minBreakTicks 0 (мгновенное срабатывание зоны).
27. **Категория блоков**: в зону допускаются только кирочные блоки —
    теги `stone`/`metal`/`diamond_pick_diggable` + явный список (лёд,
    рельсы, руды, спавнер…). Дерево/доски/горшки/лестницы/земля —
    `wrong_tool`, не ломаются (как ванильная кирка по скорости, но жёстче:
    зона их просто не трогает).
28. **Урон приведён к киркам**: 2/3/4/2/5/6 по материалам.
29. **Порядок в креативе**: молоты внутри группы «Кирки» сразу после
    ванильных кирок; порядок материалов задаёт item_catalog (кастомные
    секции между ванильными невозможны — позиция «в группе кирок»
    ближайшая к «сразу после кирок»).
30. **Иконка предмета**: `"minecraft:icon": "<ключ>"` строкой (формат
    1.26.40) вместо объектной формы — актуальный стандарт.
31. **Текстуры**: силуэт отцентрован (поля ~1-2px), голова увеличена
    (9.3×16.4 против 7.7×15.2); иконки паков — обложки: градиент, сетка
    блоков, свечение, отражение на «полу», искры, бевел-рамка.

32. **Книга «Расширение I» — два варианта**: (1) ванильная book_enchanted
    с перекраской по ролям и эмблемой, повёрнутой на угол книги (угол
    измерен PCA силуэта, все 152 пикселя сохраняются — проверяется
    ассертом); (2) книга с нуля: индиго-градиент, корешок со стежками,
    золотые углы, застёжка со скважиной, блок страниц, лента с V-вырезом,
    эмблема 3×3→5×5 в локальных осях книги, искры. Обе — 16×16 и 32×32.
